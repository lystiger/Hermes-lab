# Secrets handling investigation

## Findings

- **High likelihood, high impact: inherited credentials.** The legacy launcher copies the entire server environment into its runner (`jobs/job_launcher.py:187-200`); the subprocess backend launches agents without an `env` override (`runner/backends/subprocess_backend.py:28-29`), so it inherits the runner environment. This applies to Claude, Codex and Antigravity when run through that backend. Other backends have different process/seat environments; inheritance from the Hermes server is not established for them. Guardrail: pass a minimal allowlisted environment to each subprocess, adding only credentials required by that provider.
- **High likelihood, high impact: durable plaintext output.** The subprocess backend saves full stdout and stderr, including on timeout and cancellation, without redaction (`runner/backends/subprocess_backend.py:38-46`, `:108-120`); the reactive adapter chooses run-directory log paths and retains up to 5,000 characters of stdout in the run output (`runtime/hermes_adapter.py:1318-1319`, `:1533-1538`). The legacy launcher also combines runner stdout and stderr in a launcher log (`jobs/job_launcher.py:191-200`); Herdr uses `tee` (`runner/backends/herdr_backend.py:596-598`). Guardrail: restrict run directories and files to owner access, and redact known credential values before output is persisted. Redaction is defense in depth, not a guarantee against transformed secrets.
- **High likelihood, high impact: prompts and job data persist.** Reactive execution writes the complete effective prompt to `*_attempt*_prompt.md` (`runtime/hermes_adapter.py:939-976`, `:1071-1082`, `:1313-1314`); it includes task instructions, context and potentially mailbox content. `jobs/job_service.py:132-145` serializes the complete job detail DTO to `job.json`; the DTO includes title, tasks, errors, observations and other data (`jobs/job_service.py:52-78`). It does not automatically serialize the process environment. Agent adapters also put prompts in command arguments (`runner/agents/claude.py:68-72`, `runner/agents/codex.py:23-26`, `runner/agents/antigravity.py:17-22`), exposing them to local process inspection while running; Herdr writes the command into a wrapper with mode 0700 (`runner/backends/herdr_backend.py:575-606`). Guardrail: avoid placing credentials in goals, prompts and task output; use private run storage and retention limits, and use stdin for prompts where the CLI supports it.
- **Observed potentially sensitive artifact:** `/home/lystiger/hermes-runs/run_20261023_170127_3a393724/T2_codex_stderr.log:94` contains a database URL environment assignment with a username and password. Validity and access scope were not tested. Treat it as exposed, restrict access and rotate the credential if real.

Directory and file creation for prompt/log paths uses ordinary `mkdir`, `write_text` and `open`; permissions depend on the process umask. On this host, the resolved `~/hermes-runs` and the inspected run directory are both mode 755. `job.json` uses `NamedTemporaryFile` and atomic replacement (`jobs/job_service.py:139-145`), normally creating an owner-only file; this does not protect other artifacts or guarantee permissions in every deployment.
