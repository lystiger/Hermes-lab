# Agent model design review — Revision 2

**AGREE WITH CHANGES.** The five-way split is sound; Revision 2 needs the following corrections before implementation. Reviewed branch `design/agent-model` against the real code and D-001–D-016, including D-016’s Herdr-default decision.

1. **Distinguish runtime ID from executable.** Registry IDs are `antigravity`, `claude`, `codex`; `agy` and `gemini` are aliases. Specify canonical IDs across tasks, events and APIs while preserving persona ID `gemini`. Source: `runner/agents/registry.py:14`, `runner/agents/antigravity.py:9`.

2. **Correct the model source-of-truth claim.** Claude always passes `--model`, defaulting to adapter-selected `sonnet`; it reports only a top-level JSON `model` (`runner/agents/claude.py:70`, `runner/agents/claude.py:148`). Codex passes `--model` only when supplied and currently extracts verification data, not model identity (`runner/agents/codex.py:16`, `runner/agents/codex.py:34`). Antigravity ignores `options.model`, but captures top-level stream-event models (`runner/agents/antigravity.py:14`, `runner/agents/antigravity.py:149`). Store requested, effective selection and reported model separately; an ignored request must never appear as the model used.

3. **Define the actual run persistence work.** `/jobs/{id}/runs` uses live `ExecutionManager` records, then reconstructs from durable events; there is no independent model-aware run store (`jobs/job_service.py:366`, `jobs/job_service.py:451`). Adapter result metadata is not copied into `AgentRun.metadata`, nor included in completion events/projected back (`runtime/execution.py:243`, `runtime/events.py:427`, `runtime/storage/projector.py:290`). Cover success, failure, cancellation and restart, plus a bounded cross-job query for recent instances/models.

4. **Extend D-009 end to end.** Adding allowed keys alone is insufficient: extend event binding, registry detail copying and both execution paths, with a stable run↔execution link (`runner/backends/events.py:33`, `runner/backends/execution_registry.py:33`, `runtime/hermes_adapter.py:843`). Preserve pooled-seat semantics: an idle resource carrying its previous execution’s identity is not an active instance. Define restored/stale status handling (`runner/backends/execution_registry.py:85`).

5. **Centralize role normalization before changing names.** The runner rejects everything outside builder/hardener/verifier; reactive execution accepts arbitrary roles and defaults missing roles to builder (`runner/run-hermes-sprint.py:81`, `runner/run-hermes-sprint.py:728`, `runtime/hermes_adapter.py:749`). Guards and Codex verdict validation compare literal `verifier` (`runtime/hermes_adapter.py:987`, `runner/agents/codex.py:36`). Normalize aliases before every guard, persist canonical roles, and retain historical-read compatibility beyond the one-release input window.

6. **Migrate role producers before rejecting unknown roles.** Producers include sprint specs, phase-order defaults, generated plans, replanning and recovered tasks. A single-phase job currently defaults to builder; intermediate phases become hardener and the final phase verifier (`jobs/job_launcher.py:267`). Planner contracts lowercase arbitrary roles, and planner prompts emit old names (`runtime/planning/contracts.py:31`, `runtime/planning/planner.py:39`). Define explicit defaults for missing roles and migration of stored tasks.

7. **Add research/scaffold guards; existing guards cannot enforce them.** Verifier protection is a post-execution Git-status check, not a filesystem read-only boundary (`runtime/hermes_adapter.py:464`, `runtime/hermes_adapter.py:985`, `runner/run-hermes-sprint.py:1306`). Research needs a normalized findings-path allowlist, scaffold a named-path allowlist, and integration checks for additions/deletions/renames. Transient, ignored and outside-worktree writes require stronger runtime isolation if “read-only” is a hard guarantee. Citation completeness needs separate validation.

8. **Correct repair inheritance.** D-011 distinguishes failed-task fallbacks from verification repairs: task-linked verification repairs deliberately become builder (`runtime/replanning.py:279`, `.agent/DECISIONS.md:438`). Define repair purpose separately from effective guard; blindly inheriting verifier no-mutation would prevent corrective edits. General/unlinked repairs also lack a failed task to inherit from.

9. **Put routing in shared execution policy, not personas or presentation metadata.** Define one resolver used by launcher, planner, scheduler and sprint runner: explicit task/phase settings > sprint settings > configured role defaults. Materialize and persist the resolved route before execution; specify fallback behavior. Herdr executes arbitrary adapter argv, so it hosts all three runtimes, but model selection remains adapter-dependent—Antigravity does not support it today (`runner/backends/herdr_backend.py:223`). D-016’s default still needs implementation: existing defaults remain subprocess (`jobs/job_launcher.py:289`, `runner/run-hermes-sprint.py:994`).

10. **Keep operational capabilities and reconcile them with routing.** Scheduling does depend on per-agent capabilities, including checking an explicitly assigned actor (`runtime/scheduler.py:152`, `runtime/scheduler.py:209`). Claude’s default profile lacks `implementation`, while Gemini’s includes it (`capabilities/capabilities.py:55`). The new Claude build route can therefore be rejected/rerouted. Preserve/update operational profiles independently of removing presentation claims; `resolve_agent_profile` and default registry construction consume them (`personas/persona.py:253`, `capabilities/capabilities.py:341`).

11. **Specify a compatible API/client migration.** `KNOWN_AGENT_METADATA` supplies provider, capabilities, color and presentation as well as model/phase; DTO changes must account for all of these (`personas/agent_service.py:120`, `personas/agent_service.py:136`). LysControl’s HTTP adapter tolerates null capabilities but substitutes invented `execution` capability and old presentation fallbacks (`../LysControl/src/api/adapters/httpAdapter.ts:96`). Components index/join capabilities (`../LysControl/src/features/agents/AgentLaneCard.tsx:173`, `../LysControl/src/routes/settings.tsx:127`). Migrate adapter, types, views and fixtures together. The widget consumes `/execution`, not `/agents`; additive fields are compatible if existing resource/state semantics remain (`../LysOmarchy/plugins/lysomarchy.hermes/HermesModel.js:15`, `../LysOmarchy/plugins/lysomarchy.hermes/HermesModel.js:54`).

12. **Make persona restrictions structural.** Sanitization removes only top-level privilege keys; arbitrary behavioral rules and system fragments still enter the prompt (`personas/persona_loader.py:36`, `personas/persona_loader.py:73`, `personas/persona_loader.py:91`, `personas/persona.py:98`, `personas/persona.py:105`). Restrict prompt-visible catalog fields to voice, keep role/controller rules outside persona data, and validate provenance explicitly—the current loader/schema discards it. Prompt precedence cannot guarantee “voice not content”; preserve raw artifacts/results and confine any styled rendering to separate display text. Also remove invented fallback prose and the malformed fallback constructors (`personas/persona.py:239`, `personas/persona_loader.py:105`).

13. **Reorder delivery and resolve contradictions.** Establish role/routing/schema contracts first; implement H3 persistence/events and H4 capability/readiness discovery before H2 derives status/history; migrate clients before removing legacy fields. H1 may proceed independently after schema restrictions. `supports_agent` means compatibility, not installed/authenticated readiness (`runner/backends/base.py:48`). Remove superseded no-sheet/H5 text (`docs/design/agent-model.md:31`, `docs/design/agent-model.md:54`, `docs/design/agent-model.md:66`), define Hermes as a system persona without requiring a launchable adapter, and add migration/restart, alias-guard, routing-capability and client compatibility acceptance checks.
